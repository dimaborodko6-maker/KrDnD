# Инструкции для работы с Kr6DnD

Браузерная кооперативная tower defense: Node.js, CommonJS, Express, `ws`, обычные HTML/CSS/JS. Сборки фронтенда нет. Сервер управляет одной общей партией.

README предназначен для игроков и мастера. Инструкции по изменению проекта начинаются здесь; подробные рецепты остаются в профильных документах.

- [Архитектура, источники данных и изолированный запуск](docs/development.md).
- [Рецепты сущностей](docs/entities.md) и [проверяемый пример моба и волны](docs/examples/enemy-and-wave.json) — пример не является полным каталогом для импорта.
- [Серверные команды](docs/websocket.md), [вмешательства мастера](docs/master-controls.md), [локализация](docs/localization.md).
- [Подготовка релиза и восстановление](docs/release.md).

`npm run check:content` проверяет каталог и пример серверными валидаторами без запуска игры и записи пользовательских данных.

## Правила изменений

1. Сначала найди существующее поведение и соответствующий тест через `rg`. Ищи функции и ID, а не запоминай номера строк.
2. Для нового контента сначала используй уже поддерживаемые поля и `traits`. Описание способности само по себе не добавляет механику. Характеристики мобов, награды (`reward`), баланс башен и бюджет волн рассчитывай по [спецификации баланса](#математический-баланс-и-формулы-спецификация-для-ии-агентов). Это проектная модель, а не подтверждение текущих чисел движка; существующие правила не меняй без задачи на баланс.
3. `public/gamedata.js` содержит исходные определения. Существующий `gamecatalog.json` заменяет **весь** каталог мобов и волн при старте. Он не содержит героев и башни. Укажи, какой слой меняешь. Новый встроенный ID должен присутствовать и в сохранённом каталоге: иначе сервер отклонит запуск. Перенос пользовательских данных планируй явно, по рецепту моба.
4. Не меняй `gamestate_save.json`, `gamecatalog.json`, `scenes.json`, `logs/` и `.codex-backup/` ради проверки кода. Меняй каталог только когда задача требует изменения сохранённого контента. Не сбрасывай пользовательскую партию.
5. Для ручной игры используй временную директорию и отдельный порт по инструкции в `docs/development.md`.
6. Правила боя и проверка входных команд остаются на сервере. Клиентский предпросмотр должен соответствовать расчёту сервера.
7. Всё сохраняемое и откатываемое состояние держи в `gameState` или вложенных сущностях. Модули читают актуальный мир через `getState()` — откат может заменить объект целиком.
8. Координаты с нуля, клетка — `grid[y][x]`. Не подменяй круглый радиус квадратным; используй метрику существующего правила.
9. Обычный урон врагу проводи через `mobTraits.damage()` на сервере либо `ctx.damage()` в способностях башен. Соблюдай существующие точки смерти, награды и удаления; нельзя терять щиты, взрыв при смерти или спешивание.
10. Не переименовывай ID без проверки волн, призыва, сцен и сохранённых экземпляров. Не добавляй новые зависимости, массовое форматирование и рефакторинг вне задачи.
11. При изменении функционала обновляй соответствующую документацию: `README.md` — начало игры и правила для участников, `AGENTS.md` — инструкции агентам и проектные спецификации, `docs/` — подробные руководства. Не возвращай технические инструкции в README. Источник полного руководства — `docs/playing-guide.md`, его поставляемая HTML-версия — `public/guide.html`; изменения правил отражай в обеих версиях.

## Карта реализации и диагностика

[Полная карта исходных файлов](docs/development.md#sources-of-truth) описывает актуальные слои данных. Дополнительные серверные башни задаются в `public/tower-catalog-data.js`; браузерный каталог черновиков не управляет боем.

Основные поля `gameState`: `gold`, `wave`, `phase`, `gamePeriod`, `availableTowerTypes`, `baseHp`, `gridWidth`, `gridHeight`, `grid`, `players`, `enemies`, `soldiers`, `demolishVote`, `rosterVote`, `actionLogs`, `debugLogs`, `roundCounter`. `moveEnemies()` выполняет ход волны, `castAbility()` — действие героя, `towerCombat.fireRound()` — атаки башен. `findShortestPath()` ищет путь по `road`, `spawn`, `castle` без диагоналей. Ожидающие группы хранятся в `pendingSpawns` и удерживают волну активной.

Express раздаёт `public/`, включая стартовую страницу `index.html`; `/gamedata.js` отдаёт актуальный каталог динамически. Файлы из корня проекта через статику не доступны. Пути: `KR_SAVE_FILE` — партия, `KR_CATALOG_FILE` — каталог, `KR_SCENES_FILE` — библиотека, `KR_LOG_FILE` — журнал, `PORT` — порт. Каталог и библиотека по умолчанию находятся рядом с сохранением. `scripts/start.cjs` умеет копировать стартовые данные из `defaults/`, но текущий `npm start` запускает `server.js` напрямую; не считай эти пути запуска тождественными.

`broadcastState()` планирует сохранение через 500 мс после последнего обновления. Редактирование JSON при работающем сервере не обновляет мир в памяти. При ошибке обработчика команды мир восстанавливается до команды. Сервер держит одно соединение мастера; автоматического переподключения клиентов нет. Приложение рассчитано на доверенную локальную сеть: пароля и учётных записей нет. При изменении сетевого режима проверь оба WebSocket-клиента и доступ к командам.

Если `npm ci` сообщает о несовпадении `package.json` и lock-файла, зафиксируй эту причину непрохождения проверок. Не обновляй зависимости и lock-файл в задаче только на документацию.

`npm run benchmark:towers` измеряет только фазы атак в синтетических сценах, без движения, сети и браузера. Настроенный ESLint вызывается через `npm run lint`; он не входит в `npm run check`. Полная проверка проекта — `npm run check` (синтаксис, контент, английский текст продукта, тесты).

### Общий файл логов

При обычном запуске через `npm start` или `node server.js` сервер автоматически создаёт **`logs/game.log`**. Полный путь выводится в терминале. Логи мастера, игроков и обоих редакторов собираются в этот файл на компьютере сервера.

В файл записываются:

- запуск сервера, сообщения консоли, ошибки загрузки и сохранения, аварии Node.js со стеком вызовов;
- подключения и отключения WebSocket, входящие команды, отклонения и ошибки обработчиков;
- хроника действий и технические расчёты боя, включая записи, уже исчезнувшие из журнала на экране;
- ошибки JavaScript, необработанные Promise, `console.warn` / `console.error`, ошибки загрузки ресурсов и соединений в браузерах.

Для команд и боевых событий сохраняются номер волны и раунда, период партии, казна и здоровье базы. Идентификаторы сессии сервера, команды и соединения помогают сопоставлять записи. Ошибки браузера содержат экран, идентификатор вкладки, имя игрока при наличии, время клиента и последнюю отправленную команду. Каталоги, карты и тексты заметок целиком в журнал не копируются; длинные поля сокращаются.

Формат — UTF-8, одна JSON-запись на строку. Поле `time` содержит время сервера в UTC (`Z`); для Москвы прибавьте три часа. Файл дополняется после перезапуска. Очистка технического журнала в интерфейсе и откат партии не удаляют записи из файла. Автоматической очистки или ротации нет, поэтому между партиями можно остановить сервер, скопировать журнал для диагностики и удалить `logs/game.log`: следующий запуск создаст его заново. Каталог `logs/` исключён из Git.

Смотреть последние записи в PowerShell:

```powershell
Get-Content .\logs\game.log -Encoding UTF8 -Tail 30 -Wait
```

При необходимости задайте другой путь **перед запуском**:

```powershell
$env:KR_LOG_FILE = 'C:\Games\Kr6DnD\game.log'
npm start
```

Каталог для журнала создаётся автоматически. После обновления кода перезапустите сервер и обновите страницы на всех устройствах, чтобы включить сбор браузерных ошибок. При недоступном сервере браузер держит до 100 записей в памяти и повторяет отправку; закрытие вкладки, сбой браузера или резкое отключение устройства не гарантируют доставку. Файл логов через HTTP не раздаётся; для разбора ошибки передайте сам `game.log`.

## Математический баланс и формулы (Спецификация для ИИ-агентов)

> **Статус модели:** формулы и таблицы перенесены из прежнего README без ребаланса данных. Это требования к проектированию нового контента, а не описание всех текущих значений. В частности, расчётный бонус зачистки не доказывает, что сервер его выдаёт. Перед изменением существующего баланса сравни модель с кодом и тестами; неоднозначные модификаторы согласуй в рамках задачи.

> **Обязательно к исполнению всеми ИИ-агентами:** При добавлении, изменении или генерации врагов, башен, волн кампании и наград **запрещено** выставлять параметры «на глаз». Любая новая сущность должна рассчитываться и валидироваться по формулам ниже.

### 1. Физика движка и базовые допущения
- **Базовый раунд:** 1 тик боевого цикла (`moveEnemies`, `fireRound`).
- **Длина дорожки ($L$):** ~12–16 клеток (в среднем 14).
- **Экспозиция моба под огнем башни ($T_{\text{exp}}$):** при радиусе башни $R$ и скорости моба $V$:
  $$T_{\text{exp}} \approx \frac{2R + 1}{V}$$
  Скорость $V=2$ сокращает время пребывания под огнем в 2 раза, поэтому скорость является прямым множителем живучести.
- **Эффективное здоровье (EHP):**
  $$EHP = \frac{HP}{1 - \text{Resist}_{\text{eff}}} \times \frac{1}{1 - \text{Dodge}}$$
  где $\text{Resist}_{\text{eff}} = 0.6 \cdot \frac{\text{Armor}}{100} + 0.4 \cdot \frac{\text{MagicRes}}{100}$ (взвешенное среднее сопротивление). При $Dodge = 30\% \Rightarrow \frac{1}{1 - 0.3} \approx 1.43$.

---

### 2. Формула индекса сложности врага ($CR_{\text{mob}}$) и награды ($Bounty$)

Эталоном **$CR = 1.0$** является базовый Бандит (`bandit`: HP=40, Защита=0, Скорость=1, Урон=3).

$$CR_{\text{mob}} = \left( S_{\text{mob}}^{0.60} \times A_{\text{mob}}^{0.40} \right) \times K_{\text{traits}}$$

#### Компоненты формулы:
1. **Фактор живучести ($S_{\text{mob}}$):**
   $$S_{\text{mob}} = \left(\frac{EHP}{40}\right) \times V^{0.75}$$
   *(Для $V=1 \rightarrow 1.0$; для $V=2 \rightarrow 2^{0.75} \approx 1.68$).*
2. **Фактор атаки ($A_{\text{mob}}$):**
   $$A_{\text{mob}} = \frac{D_{\text{eff}}}{3}$$
   - Ближний бой: $D_{\text{eff}} = \text{meleeDmg}$.
   - Дальний бой: $D_{\text{eff}} = \text{rangedDmg} \times 1.25$ (бьёт вне блока защитников).
   - Клив / Сплэш (`aoeCleave`): $D_{\text{eff}} = \text{meleeDmg} \times 1.75$.
   - Казнь (`executeThreshold` $\ge 0.25$): $D_{\text{eff}} = \text{meleeDmg} \times 1.33$.
3. **Модификатор механик ($K_{\text{traits}}$):**
   - Полёт (`isFlying: true`): $\times 1.25$ (игнорирует казармы, бомбарды и наземные блоки).
   - Призыв (`summoning`): $+ \text{суммарный } CR \text{ призванных миньонов за 3 раунда}$ ($\approx +4.0$ для Заклинателя воронов).
   - Лечение союзников (`healPower`): $+ \frac{\text{healPower}}{12}$ ($\approx +2.0$ для Орка-шамана).
   - Спешивание при гибели (`goblin_rider`): $+ CR_{\text{spawned\_mob}}$ ($+0.9$ за Гоблина).
   - Урон базе (`livesTaken` $\ge 2$): $\times 1.25$.

#### Формула золотой награды за убийство ($Bounty$):
$$Bounty = \max\left(1, \; \operatorname{round}(CR_{\text{mob}} \times 4.5)\right)$$

### 3. Формула боевой мощи Башен ($Power_{\text{tower}}$) и цен ($Cost$)

#### А. Атакующие башни (Лучники, Маги, Артиллерия):
$$Power_{\text{tower}} = D_{\text{avg}} \times \left(\frac{\text{Range}}{3}\right)^{0.5} \times M_{\text{type}} \times M_{\text{init}} \times M_{\text{target}}$$
- $D_{\text{avg}} = \frac{\text{minDamage} + \text{maxDamage}}{2}$.
- $M_{\text{type}}$: Физический = $1.0$; Магический = $1.15$ (игнорирует броню).
- $M_{\text{init}}$: Фаза 1 ($Init \ge 16$, стрельба до хода мобов) = $\times 1.10$; Фаза 2 ($9..15$) = $\times 1.00$; Фаза 3 ($Init \le 8$) = $\times 0.92$.
- $M_{\text{target}}$: Земля+Воздух = $\times 1.15$; Только земля (`noAir`) = $\times 0.90$; AoE-сплэш = $\times 1.65$; Цепная молния (до 4 целей) = $\times 2.00$.

#### Б. Казармы (Удержание дороги):
$$Power_{\text{barracks}} = (N_{\text{soldiers}} \times \text{Damage}) + 0.15 \times (N_{\text{soldiers}} \times EHP_{\text{soldier}})$$

#### В. Баланс стоимости по уровням ($Cost_{\text{cumulative}}$):
$$Cost_{\text{cumulative}} \approx 8.5 \times Power^{1.12}$$

---

### 4. Формула боевой силы Героев ($Power_{\text{hero}}$)
$$Power_{\text{hero}} = \frac{EHP_{\text{hero}}}{10} + (15 \times \text{blockLimit}) + DPR_{\text{avg}}$$
- $EHP_{\text{hero}} = \frac{HP_{\text{max}}}{1 - \text{Armor}/100} + \text{Shield}$.
- $DPR_{\text{avg}} = \text{Dmg}_{\text{dice}} + \text{STAT\_MOD} + \frac{\text{UltimateDmg}}{5} + (\text{HealPerRound} \times 1.5)$.
- Стартовый герой 1 уровня (27 очков характеристик) имеет $Power \approx 65–85$. Отряд из 3 героев даёт со старта $\approx 220$ распределённой боевой мощи.

---

### 5. Экономический цикл и баланс кампании (Решение проблемы Пункта 3)

#### А. Бюджетирование волн по сложности:
Суммарная сложность волны:
$$CR_{\text{wave}} = \sum_{j} CR_{\text{mob}_j}$$
Целевая кривая прогрессии сложности (7 волн, стартовый $CR_1 = 12$, шаг $+45\%$):
- Волна 1: $CR = 12$
- Волна 2: $CR = 18$ (+50%)
- Волна 3: $CR = 26$ (+44%)
- Волна 4: $CR = 38$ (+46%)
- Волна 5: $CR = 55$ (+45%)
- Волна 6: $CR = 80$ (+45%)
- Волна 7: $CR = 120$ (+50%, финальный босс)

#### Б. Ликвидация «спирали смерти» (Двухфакторный золотой доход):
1. **Награды за мобов:** $CR_{\text{wave}} \times 4.5$ золота за волну.
2. **Фиксированный бонус за зачистку волны ($ClearBonus$):**
   $$ClearBonus(w) = 60 + (w \times 20)$$
   *(Выдаётся сразу при зачистке волны; гарантирует средства на перестройку обороны даже при прорывах).*

#### В. Итоговый золотой баланс кампании:
| Волна | Целевой $CR$ | Золото за мобов | Бонус зачистки | Доход за волну | Общая казна (кумулятивно) |
| :---: | :---: | :---: | :---: | :---: | :---: |
| **Старт** | — | — | — | — | **300 💰** |
| **1** | 12 | 54 💰 | 80 💰 | 134 💰 | **434 💰** |
| **2** | 18 | 81 💰 | 100 💰 | 181 💰 | **615 💰** |
| **3** | 26 | 117 💰 | 120 💰 | 237 💰 | **852 💰** |
| **4** | 38 | 171 💰 | 140 💰 | 311 💰 | **1163 💰** |
| **5** | 55 | 248 💰 | 160 💰 | 408 💰 | **1571 💰** |
| **6** | 80 | 360 💰 | 180 💰 | 540 💰 | **2111 💰** |
| **7** | 120 | 540 💰 | 200 💰 | 740 💰 | **2851 💰** |

*При таком балансе команда гарантированно имеет **~2850 золота** к 7 волне, что позволяет построить 1 башню IV уровня со всеми улучшениями (Тесла/Берта за ~1410g), 1 башню III уровня (Казармы за 340g), 1 башню III уровня (Лучники за 320g), 1 башню II уровня (Маги за 260g) и иметь 520g резерва.*

### 6. Инструкция для ИИ-агентов при генерации контента
1. **При создании нового моба:** вычислите его $EHP$, $S_{\text{mob}}$, $A_{\text{mob}}$ и $K_{\text{traits}}$. Рассчитайте $CR_{\text{mob}}$ и запишите `reward = Math.max(1, Math.round(CR * 4.5))`.
2. **При создании новой волны:** проверьте, что сумма $CR$ всех мобов волны укладывается в бюджет шага кампании ($CR_{\text{target}} \pm 10\%$).
3. **При изменении цен или урона башен:** сохраняйте показатель удельной эффективности $Power / Cost \approx 0.08 - 0.12$ для уровней I–III и высокую концентрацию мощи на клетку для уровня IV.

## Проектная спецификация арсенала и дополнительных башен

Ниже сохранена спецификация из прежнего README для работы над контентом. Перед изменениями сверяй числа и реализованные эффекты с `public/tower-catalog-data.js`, `server.js` и [правилами боя башен](docs/tower-combat.md). Поля и описания сами по себе не гарантируют механики: в частности, `hiddenFromPlayers` нужно отдельно проверить на поддержку сервером и клиентом. Текущий интерфейс также поддерживает прямое изменение набора в подготовке; голосование — отдельный путь команд.

### Предматчевый выбор арсенала башен и командное голосование

В периоде подготовки игроки формируют активный боевой арсенал команды из **5 базовых типов башен**.

#### 1. Механика голосования команды (`rosterVote`)
- Любой подключённый игрок в периоде подготовки может открыть витрину арсенала башен, выбрать желаемый состав из 5 типов и нажать **«Предложить набор команде»**.
- Если в партии один игрок — набор применяется немедленно.
- Если игроков несколько — запускается командное голосование (по аналогии с голосованием за снос):
  - Сервер переходит в состояние `rosterVote: { initiator, proposedTypes, votes }`.
  - У всех участников открывается плашка голосования с предложенным составом башен и кнопками **«👍 За»** и **«👎 Против»**.
  - При единогласном одобрении набор башен применяется в `gameState.availableTowerTypes`. При голосе «Против» предложение отклоняется.
  - Мастер в своём пульте видит ход голосования и может принудительно утвердить или отменить предложение.
- Набор нельзя изменить, если на карте уже построена башня типа, который пытаются убрать (сначала требуется снос).

#### 2. Спецификация новых башен и веток развития

##### ⛏️ Аванпост Дворфов (`dwarf_1` ➔ `dwarf_2` ➔ `dwarf_3` ➔ `dwarf_4`)
- **Тип прокачки:** 1 прямая линия (I ➔ IV).
- **Роль:** Гарнизон ближнего боя + пассивный доход в казну команды.
- **Шахтёрская механика:** Пока в радиусе башни нет врагов, дворфы добывают золото в шахте (1 ур. — **4 G**, 2 ур. — **7 G**, 3 ур. — **10 G**, 4 ур. — **15 G** за ход). При появлении врагов бойцы выходят на дорогу и блокируют продвижение.
- **Характеристики по уровням:**
  - I ур. (70 G): 3 бойца, 40 ХП, 5% брони, урон 4, доход +4 G/ход.
  - II ур. (+65 G): 3 бойца, 65 ХП, 10% брони, урон 7, доход +7 G/ход.
  - III ур. (+100 G): 3 бойца, 100 ХП, 15% брони, урон 12, доход +10 G/ход.
  - IV ур. (+235 G, «Горная Твердыня»): 3 бойца, 150 ХП, **20% брони**, урон 18, доход +15 G/ход.
- **Способности IV уровня:**
  - 💰 **«Глубинная жила» (Пассивная):** 25% шанс удвоить доход за ход (30 G), 5% шанс утроить доход (45 G).
  - ⚡ **«Внезапное появление» (КД 4 раунда):** При появлении из шахты оглушает 1 врага на следующий ход волны.
  - 🧨 **«Бочонок гномьего пороха» (КД 3 раунда):** Бросок бочонка в заблокированных врагов на 20–35 урона огнём и оглушение на 1 ход.

##### 💀 Башня Некроманта (`necro_1` ➔ `necro_2` ➔ `necro_3` ➔ `necro_4`)
- **Тип прокачки:** 1 прямая линия (I ➔ IV).
- **Роль:** Дистанционная тёмная магия + призыв скелетов-блокеров.
- **Характеристики по уровням:**
  - I ур. (100 G): урон **8–12** (Магический), дальность 3, лимит **2 скелета**.
  - II ур. (+100 G): урон **15–23** (Магический), дальность 3, лимит **3 скелета**.
  - III ур. (+140 G): урон **25–39** (Магический), дальность 3, лимит **4 скелета**.
  - IV ур. (+180 G, «Зиккурат Архинекроманта»): урон **38–58** (Магический), дальность 3, лимит **4 скелета**.
- **Способности IV уровня:**
  - ☠️ **«Ядовитая трясина» (КД 6 раундов):** Заливает клетку дороги ядом на 3 хода. Наносит 15 чистого урона за ход всем на клетке (со значком жижи на карте и иконкой отравления у врагов).
  - 🦴 **«Дополнительные лопаты» (Пассивная):** Расширяет лимит нежити до **7 скелетов**.
  - ⚔️ **«Костяной Рыцарь» (Пассивная):** Первый призванный скелет становится тяжёлым Рыцарем (ХП 55, броня 30%, блок 2 врагов, урон 12).

##### 🔮 Королевский Маг (`royal_mage_1` ➔ `royal_mage_2` ➔ `royal_mage_3` ➔ Развилка IV)
- **Тип прокачки:** Развилка на IV уровне (Придворный Маг / Жрица Света).
- **Уровни I–III:**
  - I ур. (100 G): урон **10–18** (Магический), дальность 3.
  - II ур. (+100 G): урон **22–34** (Магический), дальность 3.
  - III ур. (+140 G): урон **36–54** (Магический), дальность 3.
- **Развилка IV.А: 🧙‍♂️ «Придворный Маг» (`mage_court`):**
  - Стоимость: +175 G. Урон **50–80** (Магический), дальность **4 клетки**.
  - 📖 **«Старая магическая книга» (КД 5 ходов):** Совершает 3 атаки подряд за один ход волны.
  - 🔮 **«Магический резонанс» (КД 4 раунда):** На 2 хода повышает урон всех союзных башен в своём радиусе на +25%.
- **Развилка IV.Б: 🕊️ «Святилище Жрицы Света» (`mage_priestess`):**
  - Стоимость: +130 G. Урон **24–38** (Магический), дальность 3 клетки.
  - 💖 **«Молитва исцеления» (Каждый раунд):** Восстанавливает **1d4+3 ХП всем живым** союзникам в радиусе 2 клеток (скелеты не лечатся).
  - 🌿 **«Очищающее благословение» (КД 3 раунда):** Снимает яд, оглушение, кровотечение и замедление со всех союзников в радиусе.
  - ☀️ **«Карающий луч» (КД 2 раунда):** При блокировании врага союзником бьёт монстра вспышкой на 20 магического урона и даёт ему помеху (Disadvantage) на следующую атаку.

#### 3. Настройка скрытия башен для мастера (`hiddenFromPlayers`)
- В каталоге и редакторе башни поддерживают флаг `hiddenFromPlayers: true`.
- Башни с этим флагом не отображаются в каталоге игроков и не могут быть выбраны игроками, пока мастер не откроет их (снятием флага в каталоге или по сценарию кампании).
